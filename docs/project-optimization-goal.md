```text
完成 Turbo AI Server 的第一轮生产化优化。在不改变已公开 API 路由和前端调用契约的前提下，消除账户密码明文存储与回传、限制生产环境跨域来源并关闭敏感数据日志；让 global.json 使用有效的 .NET SDK feature band；将测试替换为仓库内自包含、跨平台的测试数据，并使 `dotnet test Turbo-Auth.sln --configuration Release --nologo` 通过且不产生 NU1701 警告。同步补充部署与安全配置说明。每个阶段均运行测试并记录结果；如安全改动会影响现有客户端，先提供兼容期和回滚开关。达到全部验收标准前不要停止。
```

这符合 Goal 模式所要求的「预期结果、约束条件、验证」三要素；目标文本同时是首条任务提示和完成条件。参考：[OpenAI 官方长时间运行工作文档](https://learn.chatgpt.com/zh-Hans/docs/long-running-work)。

## 项目现状

这是一个面向 AI 服务的 ASP.NET Core 后端，当前目标框架为 .NET 10。它提供：

- AI 聊天：通过策略/处理器适配 OpenAI、Google、Anthropic、阿里云等供应商。
- AI 媒体和图像任务：包含 OpenAI 媒体、APIMart 等接口。
- 账户、角色、JWT 鉴权，以及管理员的模型与密钥管理。
- 聊天历史、消息和任务同步；MySQL 作为持久层，Redis 可选作为分布式缓存。
- `Turbo-Kit` 提供 TXT、Word、PDF 文档文本提取，`Turbo-Kit-Test` 为其测试项目。

入口位于 `Turbo-Auth/Program.cs`，控制器直接依赖 Repository、聊天处理器与密钥池。两个 DbContext（`AuthContext`、`KeyContext`）共享 MySQL 配置；启动时加载可用供应商密钥到内存池。前端由独立的 Angular 仓库构建后放入 `wwwroot/ai` 与 `wwwroot/admin`。

## 优先级与实施阶段

### P0：安全封口（必须先完成）

| 问题 | 仓库证据 | 目标改动 | 验收标准 |
| --- | --- | --- |
| 密码以明文保存、比较和返回 | `AuthController` 直接以密码查询；`AccountRepository` 多个管理接口返回 `Password`。 | 使用成熟的密码哈希组件（如 ASP.NET Core `IPasswordHasher`），新增安全 DTO，任何响应均不含密码或哈希。提供受控迁移：首次成功登录时升级旧记录，或执行一次性迁移。 | 注册后数据库中不存在对应明文；正确/错误密码登录覆盖测试；所有账户 API 响应的 JSON 不含 `password`；迁移与回滚步骤经演练。 |
| 生产环境 CORS 允许任意来源并携带凭据 | `Program.cs` 允许任意 origin、header、method 和 credentials。 | 将允许来源改为配置白名单；开发环境可保留显式的本地来源。 | 未列入来源收到 CORS 拒绝；配置的用户端与管理端来源可成功预检和调用；没有 `AllowCredentials` 与任意 origin 组合。 |
| 敏感信息与疑似部署连接信息暴露风险 | DbContext 无条件启用 EF Core 敏感数据日志；`appsettings.json` 和 example 文件均被 Git 跟踪。 | 仅在明确的本地开发开关下启用详细/敏感日志；轮换所有已提交或疑似已提交的凭据；移除真实值，使用环境变量或受管密钥注入。 | 生产配置不启用敏感日志；仓库扫描无密码、令牌、连接串真实值；部署文档说明所需环境变量，不打印其值。 |
| 错误信息直接写入聊天响应 | 聊天控制器向客户端写入 `Exception.Message`。 | 使用统一问题响应/错误码，服务器侧结构化记录异常并脱敏。 | 集成测试确认 5xx 响应不暴露供应商密钥、连接串、文件路径或原始异常消息；日志可凭 correlation ID 定位。 |

**实施状态：** 密码服务已支持旧明文记录在成功登录后升级为哈希，账户响应已移除密码字段；生产数据库必须先按 `Turbo-Auth/Resources/account/upgrade-password-column.sql` 扩容列。CORS 已改为配置白名单，未配置时拒绝跨域请求。凭据轮换不可回滚，仍需由环境负责人完成。

### P2：可靠性、性能与可维护性

| 方向 | 目标改动 | 验收标准 |
| --- | --- | --- |
| HTTP 调用 | 通过 `IHttpClientFactory` 配置命名/类型化客户端、超时、重试边界与取消令牌；移除控制器和处理器中的即时 `new HttpClient()`。 | 压测期间连接数稳定；超时、供应商 429/5xx 有测试；取消请求不继续消耗上游配额。 |
| 启动与密钥池 | 使启动阶段显式等待 `LoadKeys()`，提供健康检查、刷新失败告警与最近一次成功加载时间。 | 未完成初始密钥加载的实例不接流量；刷新失败可观测且不清空最后一份可用池。 |
| 数据访问 | 消除 N+1 账户角色查询，补齐唯一索引、分页和取消令牌；为写操作统一事务边界。 | 账户列表在固定样本中查询数受控；重复用户名/邮箱由数据库约束保护；并发写入测试通过。 |
| API 质量 | 增加 API 版本策略、OpenAPI 生产暴露策略、统一 Problem Details、速率限制和请求大小限制。 | 关键 API 有集成测试与 OpenAPI 契约；限流/超限响应确定；破坏性变更有弃用期。 |
| 可观测性 | 引入结构化日志、请求关联 ID、健康检查、指标和审计事件（不记录密钥与密码）。 | 可从一个请求 ID 追踪应用、数据库和供应商调用；健康端点区分存活与就绪；安全日志脱敏测试通过。 |

## 非目标与约束

- 不修改现有已公开路由、前端 URL 或供应商模型标识；若必须变更，先新增兼容接口并制定弃用期。
- 不把真实数据库、JWT、供应商密钥或用户数据写入测试、示例配置、日志或提交历史。
- 不在未确认 NPOI 许可前写入接受声明。
- 先完成 P0，再开始 P1；P2 可拆分为独立 Goal，但不得与 P0 在同一工作树并发写入。
- 数据库变更必须提供向前迁移、备份、验证、回滚窗口和失败处置说明。

## 里程碑与停止条件

1. **M1 安全设计审查完成：** 威胁模型、配置清单、密码迁移方案、CORS 来源清单和凭据轮换负责人获确认。
2. **M2 P0 已部署至隔离环境：** 安全回归测试、前端跨域冒烟测试、数据迁移演练和日志脱敏检查全部通过。
3. **M3 P1 可重复构建：** SDK 配置有效，测试数据自包含，`dotnet test` 全绿，依赖与许可决定记录完整。
4. **M4 P2 按独立 Goal 交付：** 每一个可靠性/可观测性改动有负载或故障注入证据及回滚方案。

**总停止条件：** P0 与 P1 的验收标准全部满足；发布检查表、变更记录和回滚步骤入库；主分支的 CI 在干净环境中通过。若某项需要产品、安全或法务决策，暂停该项并记录阻塞原因，而不是用不安全的默认值继续。

## 推荐执行顺序

1. 建立密钥轮换和数据备份窗口，冻结账户/认证相关架构变更。
2. 编写密码、账户响应、CORS、错误脱敏的失败测试，再实施 P0。
3. 在隔离环境演练旧密码迁移与前端跨域访问，审查日志。
4. 修复 SDK 与自包含测试，处理 PDF 与 NPOI 依赖决策。
5. 将通过的测试命令、格式化和依赖审计接入 CI。
6. 把 P2 拆为 HTTP、密钥池、数据访问、API 治理、可观测性五个小 Goal，逐个完成。
