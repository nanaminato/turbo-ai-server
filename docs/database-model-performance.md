# 数据库模型与查询优化（2026-11-05）

本次按现有登录、任务同步、会话和管理查询优化 EF 模型及访问路径；没有缩短聊天正文或附件字段，没有重写账户和历史数据。

## 模型与索引

AuthContext.RuntimeModel.cs 集中维护运行时相关映射。账户用户名、邮箱、任务的账户/日期/任务 ID、刷新令牌的账户/撤销时间/过期时间增加非唯一索引，保持现有重复数据与业务语义。KeyContext 显式映射数据库已有的模型路由索引，减少 EF 模型与 SQL 定义差异。索引部署和执行计划验证见 [performance-indexes.md](performance-indexes.md)。

GenerateTask.TaskId 明确最大长度 255，与现有表一致。Images、Videos 的 JSON 转换增加顺序敏感的结构比较器、哈希和独立快照；原地增删、重排、从 null 切换等修改可被 EF 正确识别，未修改的列表不会产生无意义更新。

## 查询变化

- 消息同步通过历史的用户归属与客户端 ID 一次筛选消息，减少一次数据库往返，附件内容保持完整。
- 密钥按模型筛选采用单条 EXISTS，保留命中密钥的全部绑定，避免先物化密钥 ID 列表。
- 账户列表、按角色查询和详情直接投影公开响应，不读取密码哈希或 SecurityStamp。按角色过滤先作用于实体，再投影全部角色，避免 EF 翻译失败或丢失其他角色。
- 任务、历史与模型只读查询关闭实体跟踪；任务以日期和任务 ID 稳定排序。
- 模型绑定启停以单条 UPDATE 完成，数据库路由变更触发器继续负责版本递增。批量更新绕过 EF 跟踪；调用方不要复用先前跟踪的绑定快照判断更新后的状态。

没有全局关闭跟踪，以保留写入、权限撤销和事务处理。首次全量同步仍遵循现有协议，不截断结果；进一步降低大账户首同步的内存与锁开销需要分页快照协议，另行设计。

## 验证与边界

166 项普通后端测试通过，其中 7 项运行时回归通过 SQL 拦截器验证查询次数、账户敏感字段不被读取、租户隔离、完整绑定、批量更新范围及 JSON 原地变更持久化。隔离 MySQL 执行计划验证使用代表性数据，确认新索引命中和任务排序无需 filesort；这不代表生产环境的固定加速倍数。

开发库 niko 已应用四个索引，全部 22 张业务表行数保持不变。迁移前索引定义与行数、迁移后核对结果保存于被 Git 忽略的 TestResults/performance-upgrade-20261105-231035/。应用未被常驻启动。
