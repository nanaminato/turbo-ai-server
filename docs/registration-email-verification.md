# 注册邮箱验证

实施日期：2026-11-04。公开注册必须验证邮箱所有权，验证通过前不创建账户，也不发放登录令牌。已有账户登录及管理员创建账户不受此流程影响。

## 用户流程与接口

1. 输入邮箱，点击“发送验证码”。后端发送 6 位数字码，10 分钟内有效。
2. 填写用户名、密码、确认密码与邮箱验证码，然后提交注册。图形验证码保留为原有页面交互，服务端的安全边界是邮箱验证码及限流，不能靠客户端图形验证码绕过邮箱验证。
3. 修改邮箱会清空已填写的验证码。重发会使旧码失效；发送成功后前端按服务端返回值倒计时，服务端对同一邮箱强制 60 秒冷却。

| 接口 | 请求 | 响应 |
| --- | --- | --- |
| POST /api/auth/register/email-code | `{email}` | 202 `{code:"registration_code_sent", message, expiresInSeconds:600, resendAfterSeconds:60}` |
| POST /api/auth/register | `{username,email,password,confirm,emailCode}` | 200 空响应 |

响应里的 code 是状态标识，**绝不返回邮件中的数字验证码**。缺少/格式错误的 emailCode 返回 400 验证问题；错误、过期、重放或尝试用尽返回 `registration_invalid_code`。用户名或邮箱已使用返回 409 `registration_account_exists`。邮箱冷却返回 429 和 Retry-After；关闭注册、未配置 SMTP 或邮件发送失败返回 503 `registration_unavailable`。

## 服务端保证

- 通过密码重置已有 SMTP 配置发送注册邮件，但注册开关独立。邮件主题、正文与错误支持中、英、日三种语言。
- 邮箱先 trim / 小写归一化；数据库仅以邮箱 SHA256 为挑战行键。验证码使用安全随机数生成，只保存带独立用途前缀的 HMAC-SHA256，密钥来自 Jwt:RefreshTokenPepper，不保存验证码明文。更换该密钥会使待验证码失效。
- 每个码允许最多 5 次错误尝试；过期、用尽或成功消费后不能创建账户。SMTP 失败会作废对应挑战，不回退为无需验证的注册。
- MySQL 在行锁内检查发送冷却、修改验证次数和消费状态。使用 upsert 先取得排他锁，避免 INSERT IGNORE 后升级锁导致并发死锁。
- 验证码消费、密码哈希、账户和普通 user 角色在同一事务提交。失败会回滚，不遗留半创建账户。密码只在验证码有效后才进行账户写入。
- 公开注册还使用数据库范围的连接级锁，串行处理旧库中按排序规则比较的用户名/邮箱去重；多个实例不能通过不同邮箱并发抢占同一用户名。既有重复账户不自动合并或删除，管理员写入仍应遵守账户唯一性约定。
- 每个应用实例按远端 IP 限制发送请求 10 次/15 分钟、注册提交 30 次/15 分钟；数据库中的邮箱冷却与尝试次数由所有实例共享。代理部署须按实际可信代理配置远端 IP，不能直接信任任意客户端传入的转发头。
- 注册禁用或 SMTP 缺失时拒绝公开注册，不能通过直接请求旧注册路由绕过。当前日志不记录验证码、邮件内容或 SMTP 密码。

## 配置和数据库迁移

复用 PasswordReset 下的 SmtpHost、SmtpPort、EnableSsl、FromAddress、SmtpUsername、SmtpPassword。465 使用隐式 TLS，其他启用 SSL 的端口要求 STARTTLS，证书验证保持开启。Registration.Enabled 默认为 true；设为 false 同时关闭公开验证码发送和公开注册。PasswordReset.Enabled 仅控制密码重置，不控制注册邮件；注册验证码无需 PublicBaseUrl。

已有库停止服务并核对备份后执行一次：

```text
src/Turbo.Auth/Resources/merge/registration-email-verification.sql
```

脚本只创建 RegistrationEmailChallenges，不修改原有账户。不要在已有库重跑 init.sql。新库的 merge/init.sql 已包含这张表；旧版本库先按部署文档完成 architecture-upgrade.sql，再执行邮箱验证迁移。配置了注册 SMTP 的实例在启动前只读检查挑战表，缺少时给出明确迁移路径，不自动执行 DDL。

当前开发连接对应的数据库已完成新增表迁移，全部原有表的行数保持不变。未改 SMTP 凭据、账户或密码。新前端与后端应一起发布，旧前端未发送 emailCode 的注册请求会被拒绝；已有登录、刷新令牌与账户不受影响。

## 验证

- 后端 145 项常规测试：验证码摘要、过期、冷却、换码、跨邮箱误用、5 次尝试、重放、重名、邮件失败、禁用与 HTTP 强制校验。
- MySQL 注册测试 3 项：12 个并发发送只发一次；12 个并发提交仅创建一个账户和 user 角色；不同已验证邮箱不能并发创建同一排序规则下的用户名；以及新增迁移和启动检查。
- 原有架构 MySQL 回归覆盖新增表后的新库/升级库等价、路由触发器和数据同步。初始化脚本保持路由触发器在末尾，避免多语句执行时最后语句分号存储差异影响结构等价比较。
- 前端 87 项测试、6 项三语言校验和生产构建通过。新增覆盖发送与提交防重复、冷却、修改邮箱清码、过期响应忽略、销毁时取消和契约请求体。
- 开发库实际启动成功，Swagger 声明 emailCode 必填；缺码、未签发验证码及无效邮箱请求均返回 400。验证未发送真实邮件，也未创建真实测试账户；SMTP 投递测试使用模拟发送器，真实送达需使用用户自己的邮箱在注册页面验证。

真实 MySQL 测试仍使用忽略的 mysql.runsettings.user 和随机隔离测试库，不在开发业务库中运行并发测试。
