## SDK 升级：从 Betalgo.Ranul.OpenAI 完全迁移到 tryAGI.OpenAI 4.2.10

### 动机
- Betalgo.Ranul.OpenAI 9.2.6 不暴露 Verbosity / response_format 细粒度控制；
- Betalgo 的 `ChatCompletionCreateRequest.ReasoningEffort` 枚举仅 Low/Medium/High（无 None/Minimal/Xhigh），GPT-5 表达力受限。
- 用户选择"完全移除 Betalgo"（激进路线 C），用 AutoSDK 自动生成的 tryAGI.OpenAI 4.2.10 替换。

### 代码改动
- `Turbo.Auth.csproj`：删除 `<PackageReference Include="Betalgo.Ranul.OpenAI" ... />`，加入 `<PackageReference Include="tryAGI.OpenAI" Version="4.2.10" />`。
- `Application/Chat/OpenAiRole.cs`（新增）：从 OpenAiChatHandler 抽出共享常量 `SystemRole/Assistant/UserRole`（Google/Anthropic handler 也复用）。

  - `client.Chat.CreateChatCompletionAsStreamAsync(request, cancellationToken:)` 返回 `IAsyncEnumerable<string>`。
  - `CreateChatCompletionRequestVariant2` 字段：`Messages / Model / Stream / Verbosity / ReasoningEffort / MaxCompletionTokens / FrequencyPenalty / PresencePenalty`。
  - `VerbosityEnum`（Low/Medium/High）→ `variant.Verbosity`；`ReasoningEffortEnum`（None/Minimal/Low/Medium/High/Max/Xhigh）→ `variant.ReasoningEffort`。

  - 自定义 voice：`VoiceIdsShared.FromVoiceIdsSharedVariant1(voiceString)` 配合 `VoiceIdsShared -> VoiceIdsOrCustomVoice` 的 `op_Implicit`；内置 voice 用 `(VoiceIdsShared)VoiceIdsSharedEnum.Alloy` 等。

- `docs/technology.md`：AI SDK 行 `Betalgo.Ranul.OpenAI → tryAGI.OpenAI`。

### 关键 API 真相（4.2.10 本地版本与 GitHub main 分支不一致）
- `BetaVerbosity` / `BetaReasoningEffort` 类**只是占位 wrapper**（仅 `AdditionalProperties`），**不能**接受枚举值；不要用 `BetaVerbosityEnum`。
- `VerbosityEnum` / `ReasoningEffortEnum` 是 Variant2 上直接赋值的枚举类型。
- `ChatCompletionRequestUserMessageContentPart` 是 `partial struct`，**没有** `FromText` / `FromImageUrl` 工厂方法（`FromString` 写死 "describe the following image"，不能用作通用文本）。
- `List<ContentPart>.AsUserMessage()` **不存在**；扩展方法只支持 `string` / `byte[]`。Vision 必须显式构造 `ChatCompletionRequestUserMessage(OneOf<...>)`。
- `VoiceIdsOrCustomVoice.FromUnchecked` **不存在**；自定义 voice 走 `VoiceIdsShared.FromVoiceIdsSharedVariant1(s)` 隐式转换。
- 沙箱环境**反射被禁用**（PowerShell Add-Type 拒绝），最佳查 API 方式：直接 grep `tryAGI.OpenAI.xml`（NuGet 包内含完整 XML doc），看 `<member name="P:...">` / `M:...`。

## 修复：切换模型开关只改 ModelKeyBinds.Enable 不写 Model.Enable（导致检索不到模型 + 对话不可用）

### 触发点
用户报告：模型表 `Enable` 字段在 git 16d2da1c 之后的逻辑被改，现在检索查不到模型、对话也无法用。数据库截图里 `Models.Enable` 全为 0。

### 根因（16d2da1c 之后的 `4163497` 提交引入）
- 16d2da1c（改前）：`GetChatModelsAsync` 只按 `m.IsChatModel == true` 过滤；`ModelKeyBuilder` 只按 `mkb.Enable`（绑定层）过滤，**均不检查 `Model.Enable`**。
- `4163497`「多模型路由第一期」起：`GetChatModelsAsync` → `Where(m => m.IsChatModel && m.Enable)`；`ModelKeyBuilder` → `Where(bind => bind.Enable && bind.Model is { Enable: true, ... })`，**新增了对 `Model.Enable` 的强依赖**。
- 但 `SetEnableStatus` 至今**只更新 `ModelKeyBinds.Enable`，从不写 `Model.Enable`**（有一句调试残留 `Console.WriteLine(enable)`）。
- 结果：`Models.Enable` 一直是 0 → `GetChatModelsAsync` 返回空（模型列表查不到）→ 路由构建里 `bind.Model is { Enable: true }` 全被过滤（对话无法路由）。

## 彻底删除 Models.Enable 死字段（方案 B）

### 复盘
- 用户不接受「同步写 Models.Enable」这种治标修复，要求判断该字段是否本来就是历史包袱、能否整列移除。
- 全量 grep 后证实：`Models.Enable` 在 `4163497` 之前**没有任何读取点**（仅 schema 上的字段）。`4163497` 一次性引入 `GetChatModelsAsync` 的 `&& m.Enable`、`ModelKeyBuilder` 的 `bind.Model is { Enable: true }`、测试 `new Model { Enable = true }`，但**未引入任何对应的写入路径**——`SetEnableStatus` 一直只改 `ModelKeyBinds.Enable`，AddModel/UpdateModel 仅做透传。
- 因此删除字段比「让 SetEnableStatus 同步写」更干净：避免给一个没有人在乎的字段发明"权威来源"。

### 代码改动
- `Models/Suppliers/Model.cs`：删除 `public bool Enable` 属性。
- `Repositories/Catalog/ModelRepository.cs`：
  - `GetChatModelsAsync` 退回 `.Where(m => m.IsChatModel)`（去掉 `&& m.Enable`）。
  - `AddModelAsync` 删除 `Enable = model.Enable` 透传。
  - `UpdateModelAsync` 删除 `innerModel.Enable = model.Enable` 透传。
  - `SetEnableStatus` 保留为只改 `mkb.Enable`（撤回上一轮的同步逻辑）。
- `Application/Routing/ModelKeyBuilder.cs`：`.Where(bind => bind.Enable && bind.Model is { ModelValue: not null })`（去掉 `{ Enable: true }`）。
- `tests/Turbo.Auth.Tests/ChatRoutingTests.cs`：两处 `new Model { Enable = true, ... }` 删除 Enable。

### SQL 改动
- `Resources/merge/init.sql`：Models 表删掉 `Enable tinyint(1) not null`。
- 新增 `Resources/merge/upgrade-drop-models-enable.sql`：`ALTER TABLE Models DROP COLUMN Enable;`（已有库备份后单次执行）。
